# 辞書・LLM補助による少数例レビュー

更新日：2026年9月20日。対象はニュース・政府文書等を含む記事見出し生成。対象言語の専門読者による独立評価は現時点で確保できていない。研究者本人はWiktionary等の辞書とLLMによる語句・文脈説明を使って読解できると申告した。このレビューは生成・選択の数値指標を補う定性分析であり、ネイティブ話者評価や「内容的正しさ」の確定ではない。

[Fu and Liu (2025)](https://aclanthology.org/2025.findings-emnlp.587/) は、多言語LLM判定の一貫性が十分でなく、低資源言語で特に不安定と報告している。したがってChatGPT等の回答だけで正解ラベルを付けない。LLMは翻訳・語釈・疑問点の候補を出す補助者であり、研究者が根拠を照合し、判定不能を残す。

## レビューする例の選び方

本実験の評価集合とモデル出力を固定した後、各対象言語で16件を抽出する。見出し生成の自動指標の高低と4択選択の正誤を組み合わせた4区分から各4件を固定seedで抽出する。区分が4件未満ならその件数と不足理由を記す。これは失敗機序の代表例を探すための層化抽出であり、失敗率の母集団推定には使わない。開発用20件は含めない。対象言語数を決める前に、総レビュー数を増やすかは判断しない。

## 1件ごとの手順

1. 記事ID、言語、本文、生成見出しだけを提示し、モデル条件・自動スコア・参照見出しは最初は伏せる。氏名等が含まれる場合は研究ノートの公開範囲に注意する。
2. LLMに「本文と見出しの主要な事実、固有名詞、数値を逐語的に説明し、読めない箇所は不明と明記」と依頼する。利用したサービス／モデル表示名、日付、プロンプト、応答をローカルの非公開作業記録に保存する。出力は原文の証拠ではない。
3. 研究者が本文の関連箇所、辞書の語釈、固有名詞・数値を照合する。辞書名、見出し語、参照日、確認できた原文箇所を記録する。辞書にない語や異なる解釈は「未確認」とする。
4. 参照見出しを開示し、生成見出しについて「中心内容の対応」「固有名詞・数値」「対象言語・文字体系」「見出しとしての形式」をそれぞれ `問題なし／問題あり／判定不能` で記録する。各判定に短い根拠を付ける。複数ラベルを許す。
5. LLM説明と原文・辞書が矛盾した場合は、無理に多数決せず「判定不能」または「LLM説明誤り候補」と記録する。参考見出し自体に問題がありそうな場合も別記する。
6. 少なくとも全件の2割を時間を置いて再確認し、判定が変わった件数を報告する。これは同一研究者の再判定であり、独立評価者間一致ではない。

## 記録項目

`review_id`、記事ID、言語、抽出区分、モデル・設定ID、本文・参照・出力のファイル参照、LLM名と実行日、プロンプト版、辞書・外部資料、確認できた原文箇所、4評価軸、判定不能の理由、再判定結果、公開可否。

本文には、機械指標（ROUGE-L、chrF等）と4択正解率を主な定量結果として示す。このレビューは、代表的な失敗と解釈上の限界を説明するために用いる。LLMの判断を正解率や「人手評価の多数決」に混ぜず、対象言語を流暢に読める評価者がいない制約を明記する。

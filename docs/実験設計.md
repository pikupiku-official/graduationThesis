# 実験設計の初期案

## 1 データ

主データはCMHGです。公式データカードでは、チベット語100,000件、モンゴル語50,000件、ウイグル語50,000件の合計200,000件が示され、各言語について3,000件を注釈した評価用サンプルが説明されています。公開データセットビューアはCSV間の列不一致で自動読込に失敗しているため、言語別ファイルを個別に取得します。取得後は、実際のファイル名、行数、列、重複、欠損、ライセンス、revisionを機械的に記録します。

保存するデータ管理情報：

- Hugging Face dataset ID
- commit hashまたはrevision
- 取得日時
- ファイル名とSHA-256
- 行数、言語、列名
- train・評価の分割方法
- 前処理スクリプトのcommit SHA

Gitには生データ本体を入れず、`data/raw/README.md`と取得マニフェストだけを残します。

評価集合の候補は `tools/prepare_eval_candidates.py` で3言語各200件をハッシュ順位で事前に選ぶ。原論文の記述に合わせ `average_score > 4`、ID重複・本文欠損・低スコア側と同一本文・開発用20件と同一IDまたは本文・高スコア側の同一本文を除外する。選出結果は `experiments/cmhg_eval_candidates.json`。これは近重複と資料種別の点検前の**候補**であり、モデル出力を見て増減・差し替えない。本実験は3言語（bo・mn・ug）を対象とし、最終評価集合は別に固定する。

## 2 実験条件

### A 直接見出し生成

記事本文（ニュース・政府文書等）を原言語のまま入力し、見出しを1件生成します。プロンプト、出力形式、デコード設定を全言語で同一にします。モデルが余計な説明を出した場合の除去ルールは、実験前に固定します。

主な出力：本文ID、言語、モデル、入力token数、出力token数、生成文、停止理由、seed、設定ID。

### B 見出し選択

本文に対して、正解見出し1件と不正解候補を複数提示し、候補番号を選択させます。最初の実装は4択とし、負例は次の2種類を分けます。

- random negative：同じ言語の別記事からランダム抽出
- hard negative：同じ言語で、語彙または話題が近い別記事の見出し。ジャンル列が存在する場合のみ同ジャンル条件を追加

候補順、候補数、負例抽出seedを固定します。候補の正解位置が偏らないようにします。モデルの自由生成で番号以外を返した場合は、再解釈で救済せず無効出力として記録します。

### C 翻訳媒介処理

原言語本文を中国語または英語に翻訳してから、同じモデルに見出し生成または選択をさせます。翻訳品質が交絡するため、翻訳器名、モデルrevision、プロンプト、翻訳結果、失敗を保存します。翻訳媒介を実施できない場合は、主実験の欠損ではなく、制約として明記します。

### D QLoRA少量適応

未注釈または学習用データだけで追加学習し、注釈済み評価データは学習に使いません。適応前後でAとBを再実行します。学習率、rank、alpha、dropout、batch、gradient accumulation、epoch、量子化設定、seed、学習時間を保存します。

## 3 評価指標

### 自動評価

- ROUGE-L：参照見出しとの系列一致
- chrF：文字n-gramに基づく一致。文字体系が異なる言語で、token単位の指標を補う
- exact match：選択課題の正解率
- invalid output rate：空出力、番号外、プロンプト再出力、文字化けなど
- input/output token length：言語別のtokenizer負荷

自動評価の前処理は、Unicode正規化、空白、句読点、文字種の扱いを明示し、原文と正規化後の両方を保存します。

### エラー分類

生成出力の少数サンプルを固定抽出し、以下のラベルを複数付与します。

- content mismatch：本文の中心内容と一致しない
- over-generalization：具体性が失われ、一般的な文になる
- named entity error：人名・地名・組織名・数値の誤り
- language mixing：対象言語以外の混在
- script corruption：文字化け・不正な文字列
- repetition：同一語句の過度な反復
- length/style issue：見出しとして不自然な長さや形式
- empty/format failure：空出力や指示形式違反

対象言語の専門読者による独立評価は未確保です。研究者本人が辞書・LLM解説を補助に少数例をレビューし、根拠と不確実性を記録します。これをネイティブ話者評価や内容的正しさの確定とは呼びません。手順は[補助的内容評価プロトコル](補助的内容評価プロトコル.md)に固定します。

## 4 最小実験セット

最初から全データを処理せず、次の順番で増やします。

1. 各言語20件：読み込み、tokenizer、生成保存の動作確認
2. 各言語100件：生成指標、選択課題、invalid出力率の確認
3. 各言語500件：主比較の傾向確認
4. 評価セット全体：計算資源と時間が許す場合のみ

小規模結果と本番結果でプロンプトや前処理を変更した場合、同一実験として比較しません。

## 6 再現性

各実験は、次のファイルを1つのrun directoryに保存します。

- `config.json`
- `prompt.txt`
- `environment.txt`
- `input_manifest.csv`
- `predictions.jsonl`
- `metrics.json`
- `errors.csv`
- `README.md`

run IDは日時ではなく、設定の短い名前とcommit SHAを組み合わせます。例：`direct_bo_mn_modelA_abc1234`。
